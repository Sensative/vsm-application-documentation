
# Application CO2-Adaptive


## Battery Reporting Module

Battery remaining esimates are measured on a weekly basis.


## Daily Rejoin Module

Should the device not be joined, it will try to rejoin on 24hr interval.


The device will do a join attempt if it is not joined and if button is pressed.


An NFC field can be applied to manually trigger a join attempt


## ADR dampening and limiting module

Adaptive LoRaWan data rate dampening and limiter module, allows to limit both adaptability rate and worst data rate / output power.
This is intended for fixed-mount devices where radio conditions are not expected to change rapidly.


## Adaptive CO2 Module

Samples CO2, temperature and humidity from the STCC4, and pressure from the barometer:

> - every dark_poll_minutes (5) while the room is dark,
> - every lit_poll_minutes (2) with the lights on, from lit_lux,
> - every high_poll_minutes (1) while CO2 is above co2_limit_ppm.

Every report carries co2_min, co2_max, co2_mean, co2_current and co2_state, and the average
temperature, humidity and pressure chosen with air_report_values, all over the samples since
the last report. A report goes out:

> - every dark_report_interval_minutes (15) or lit_report_interval_minutes (15), or
> - high_report_interval_minutes (5) above the limit,
> - when a check, every co2_check_minutes (5), or high_co2_check_minutes (5) above the limit, finds
> - CO2 moved by co2_step_ppm (50) since the last report,
> - when the lights go on or off,
> - when CO2 crosses the limit, either way.

The light level itself is not reported, it only selects the sample interval.

The sensor is factory reset each time the measurement starts, so that a unit that has waited a
long time for its first use gives sane values. The two samples after it are a fixed 390 ppm
while the sensor starts up, and are left out.

Power the CO2 sensor off in the OFF state, or when a report interval is set to 0. What was
collected so far is dropped, so the next interval starts clean.
Power the CO2 sensor on once joined, unless the measurement is turned off, and factory reset it.
The first sample is taken at once.

## Application Outputs


### Output air_humidity (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 0.01
> - Unit: %RH

The average humidity since the last report, resolution 0.01 %RH. In the report when
air_report_values has bit 2 set.


### Output air_pressure (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 0.1
> - Unit: hPa

The average air pressure since the last report, resolution 0.1 hPa. In the report when
air_report_values has bit 4 set; the barometer is not read otherwise.


### Output air_temperature (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 0.01

The average temperature since the last report, resolution 0.01 C. In the report when
air_report_values has bit 1 set.


### Output batteryPercent (confirmed)

> - Size: 1 bytes
> - Translation factor: 1

Estimated remaining % of battery in this unit based on measured use time and power for MCU, Radio, Sensors
Position Scans, and potential collateral power use.


### Output co2_current (unconfirmed)

> - Translation factor: 1

The latest CO2 sample.


### Output co2_max (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: ppm

The highest CO2 sample since the last report.


### Output co2_mean (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: ppm

The mean of the CO2 samples since the last report.


### Output co2_min (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: ppm

The lowest CO2 sample since the last report.


### Output co2_state (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Bit field
> - Values:
> -- 0 = Dark, CO2 below the limit
> -- 1 = Lit, CO2 below the limit
> -- 2 = Dark, CO2 above the limit
> -- 3 = Lit, CO2 above the limit

Bit 1 is the light: lit from lit_lux, dark again below half of it. Bit 2 is CO2 above
co2_limit_ppm, below it again co2_step_ppm under the limit. A change of either sends a report.

### Input maxPowerIndex (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Request current value: Send a2 (hex) on lora port 2
> - Update value to 1: Send a2 00 00 00 01 (hex) on lora port 2
> - *Note: It is highly recommended to ensure that you use higher level applications to update settings so that the correct version of this application is used as reference (these data may change or differ between sensors)*
> - UI: Max Power Index
> - Unit: LoraWan power index
> - Min: 0
> - Max: 255
> - Default: 255

Maximum power index to use for LoRaWan traffic, including join. The firmware's table of data rate
and TX power steps decides how high it goes, and that depends on the region: 16 today, but 13 in
US915, where the table stops at DR4. 255, the default, is the top of the table whatever the region,
so a longer table in a later firmware is used as it is. A value above the top is lowered to it,
and reads back as the index in use.

## Application Registers used (device controls)


### Register LINKCHECK_TIME

> - Request current value: Send d0 (hex) on lora port 2
> - UI:   Downlink Timeout
> - Mode: RW
> - Unit: Seconds
> - Min: 300
> - Max: 2592000
> - Default: 345600s (4 days)
How long the device goes without hearing anything from the network before it gives the network up and
goes to unjoined. Any downlink starts the time again, an acknowledgement as much as a message.

It asks for an answer well before then. From half of this time on, every uplink it sends is confirmed.
From 80% on it also sends a confirmed link check of its own, even with nothing else to send, and
repeats it until something comes back. Those uplinks count towards LORA_RESEND_COUNT as well, so when
the network has really gone away the device usually unjoins through that count before this time is up.

0 turns the check off, and then reads back as 0xFFFFFFFF. Any other value outside 300-2592000 is ignored
and the previous one kept. The firmware sets it back to 86400 on every boot, so an application that
wants another value writes it in a once rule.

In the unjoined state the application's own rejoin method is used; the firmware does not rejoin by itself.


### Register TX_POWER_RANGE

> - Request current value: Send d8 (hex) on lora port 2
Set the power index range for fast ADR, LSB = lowest, MSB = highest
Range for each is 16 (DR0/Max power) - 0 (regions best), mixing up
highest and lowest does not matter (firmware always use the highest of the two as the max).
There is a high impact on power consumption to turn this up (lower battery time).

> - UI:   TX Power Range
> - Mode: RW
> - Min: 0
> - Max: 65535
> - Unit: 2 bytes
