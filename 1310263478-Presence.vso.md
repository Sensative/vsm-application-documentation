
# Application Presence


## Application Outputs


### Output dbgBaseline (unconfirmed)

> - Size: 4 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: -32768
> - Max: 32767

The free baseline, this room's empty level. A promotion needs TObject to rise
pirPromoteDelta in one sample and to stand pirLevelMin above this, and the release
threshold is measured up from it.


### Output dbgBusyLevel (unconfirmed)

> - Size: 4 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: -32768
> - Max: 32767

The busy reference, this room's occupied level, seeded three minutes into the occupancy. The
release threshold sits a quarter of the way from the baseline up to here.

> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 7

Chip interrupt flags: 0x01 tamb shock, 0x02 motion, 0x04 presence.


### Output dbgHeld (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Boolean
> - Min: 0
> - Max: 1

Whether motion was seen at this sample, in either form: carried across the sampling interval
by motionLevel, or the chip's motion flag up right now. It holds the room nowhere - the level
decides that - and what it does carry is the quantity the safety valve counts an hour of
silence on. Read it against dbgMotionLevel for the size behind it.


### Output dbgMotdev (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 32767

Mean absolute motion signal. Read by no rule.


### Output dbgMotionLevel (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 32767

The largest |TMotion| the chip has reported since the last sample while its motion flag was
up, and zero if the flag has not been up at all. The flag hovers at its threshold when
somebody sits still, so a once a minute look catches it set only about as often as not; this
carries the interval's largest flank to the sample instead. It is what the safety valve
counts an hour of silence on.


### Output dbgState (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 4

1 Free, 2 AimBusy, 3 Busy, 4 AimFree.


### Output dbgTAmbient (unconfirmed)

> - Size: 4 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: -32768
> - Max: 32767

TAmbient, the chip's ambient temperature in hundredths of a degree. It measures the room and
not the content of the field of view, so a warming room should show here where a person does
not. No rule reads it.


### Output dbgTMotion (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 32767

|TMotion|, the chip's own motion signal, as the driver hands it over. The magnitude and
not the signed reading - the driver takes the absolute value, because that is all the
algorithm uses. It is what MOT_FLAG is raised on, so this is how a spike above the chip's
motion threshold is told apart from a flag that is merely stale.


### Output dbgTObject (unconfirmed)

> - Size: 4 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: -32768
> - Max: 32767

TObject, the raw infrared reading.


### Output dbgTPresence (unconfirmed)

> - Size: 4 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: -32768
> - Max: 32767

TPresence, the chip's own presence measure. Read by no rule: the presence flag gates the
promotion, the level decides the rest. Traced because the flag is raised on it.


### Output presence (confirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Boolean
> - Min: 0
> - Max: 1

Room occupancy. 0 => free, 1 => occupied. Free reports free; AimBusy, Busy and AimFree all
report occupied. AimBusy is where the occupancy is confirmed, not where it is announced -
the announcement is immediate, and what the confirmation buys is the right moment to seed
the reference.

## Application Registers used (device controls)


### Register LINKCHECK_TIME

> - Request current value: Send d0 (hex) on lora port 2
> - UI:   Downlink Timeout
> - Mode: RW
> - Unit: Seconds
> - Min: 300
> - Max: 2592000
> - Default: 86400
How long the device goes without hearing anything from the network before it gives the network up and
goes to unjoined. Any downlink starts the time again, an acknowledgement as much as a message.

It asks for an answer well before then. From half of this time on, every uplink it sends is confirmed.
From 80% on it also sends a confirmed link check of its own, even with nothing else to send, and
repeats it until something comes back. Those uplinks count towards LORA_RESEND_COUNT as well, so when
the network has really gone away the device usually unjoins through that count before this time is up.

0 turns the check off, and then reads back as 0xFFFFFFFF. Any other value outside 300-2592000 is ignored
and the previous one kept. The firmware sets it back to 86400 on every boot, so an application that
wants another value writes it in a once rule.

In the unjoined state the application's own rejoin method is used; the firmware does not rejoin by itself.
