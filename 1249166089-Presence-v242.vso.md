### Output dbgMotSeen (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Boolean
> - Min: 0
> - Max: 1

Whether the chip's motion flag has been seen since the last sample. This is the half of
held that an instantaneous reading misses: the flag hovers at its threshold when someone
sits still, so a once a minute look catches it set only about as often as not. Read it
against dbgFlags - motSeen set while the flag reads clear is the latch doing its work.

### Output dbgTMotion (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Unit: Value
> - Min: 0
> - Max: 32767

|TMotion|, the chip's own motion signal, as the driver hands it over. The magnitude and
not the signed reading - the driver takes the absolute value, because that is all the
algorithm uses. It is what MOT_FLAG is raised on, so this is how a spike above the chip's
motion threshold is told apart from a flag that is merely stale.

Declared here, after every other output and input, so that the reference ids in v2.4 all
keep their numbers. The two versions decode the same way for every field they share.

### Output pirOutput (confirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Boolean
> - Min: 0
> - Max: 1

Room occupancy. 0 => free, 1 => occupied. Free and AimBusy report free, Busy and
AimFree report occupied, so the two approach states never show on their own - a room
is only called occupied once the evidence has been weighed.


### Output qcPercent (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Percent
> - Min: 0
> - Max: 100

What the warning above was decided on: the share of the window during which the room
looked occupied while being reported free. The limit is 10 %, and a well placed sensor
measures 0, so this is silent in a good room - an output is only sent when it changes.


### Output qcWarning (unconfirmed)

> - Size: 1 bytes
> - Translation factor: 1
> - Unit: Boolean
> - Min: 0
> - Max: 1

Noise level high, move sensor. Raised when the room looked occupied for more than
QC_LIMIT of the time it was reported free over the last window, or when it was never
reported free for a whole day. Both mean the sensor is seeing something that is not a
person, and no threshold can be tuned around a bad placement.

### Input qcWindowSamples (unconfirmed)

> - Size: 2 bytes
> - Translation factor: 1
> - Request current value: Send b3 (hex) on lora port 2
> - Update value to 1: Send b3 00 00 00 01 (hex) on lora port 2
> - *Note: It is highly recommended to ensure that you use higher level applications to update settings so that the correct version of this application is used as reference (these data may change or differ between sensors)*
> - Unit: Samples
> - Default: 0
> - Min: 0
> - Max: 32767

Length of the quality control window, counted in samples taken while the room is reported
free. Zero switches the measurement off, and that is what it ships as - nothing is
measured and nothing is sent until an installation asks for it.

The specification's window is 72000 seconds, which is 240 samples of FREE_SAMPLING. That
is the value to set for a deployment. The window has to be one unbroken stretch of the
room being free, so 240 means twenty hours during which nobody enters - a weekend rather
than a night. For a bench check, 12 gives an answer within the hour.
